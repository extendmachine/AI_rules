# AI 项目规范

版本：0.1.1。用于约束 Codex、Claude Code 和其他 AI 的项目开发行为。
官方规范仓库：[extendmachine/AI_rules](https://github.com/extendmachine/AI_rules)，Git 地址：`https://github.com/extendmachine/AI_rules.git`。

整个目录就是项目底座，无需分发脚本或另建 templates。公共规范位于 rules，AI 从 AGENTS.md/CLAUDE.md 进入 rules/README.md。
旧 Clawtask 打包与页脚标识方案已移除，不再使用。

## 给后续 AI 的执行步骤

只有用户要求引入、复制或初始化规范时才执行以下步骤。只读审阅只交付建议，不修改文件；日常自动更新走规则 18，不重做初始化。

1. **确认来源和目标。** 使用用户指定的本地规范副本，或从上述 GitHub 仓库取得固定提交快照。目标必须是用户指定项目根目录；报告实际位置与版本，不依赖原作者电脑的绝对路径。
2. **盘点项目事实。** 查看现有目标、当前进度、活动任务、技术栈、Git 状态、微服务、接口和版本。保存复制后必须恢复的项目专用要求与有效授权，不保存秘密值。
3. **保护已有内容。** 保留业务代码、数据库、真实凭据、日志、环境及他人未提交修改。不要用空模板覆盖已填写总账。
4. **复制受控规范。** 复制公共规则、轻量入口和必要模板，公共同名内容使用源版本；依规则 06 保留、恢复项目专用补充，不盲目删掉源清单之外的本地规则。不得创建第二套公共控制规范。
5. **加载目标副本。** 从目标入口查看规则索引与本次关键变化；不要求每次修改重新全文阅读。所有后续工作使用目标内副本。
6. **审视目标项目。** 对照真实服务、接口、依赖、日志、环境、密钥、版本与分支策略识别缺项，不为小任务反复扫描全部仓库。
7. **说明整改范围。** 已授权规范化直接执行；额外业务重构、破坏性迁移或生产操作没有授权时仅列出具体建议，不因普通实现选择反复请求确认。
8. **恢复目标与状态。** 根据目标项目事实填写 FINAL_GOAL、TODO 和 AI_TASKS，清除规范源历史，恢复有效任务和授权；main 工作区为日常权威记录。
9. **补齐服务资料。** 按服务目录维护 SERVICE.md、CONTRACT.md、DEPLOY.md、REFERENCES.md 和必要的 ai-tasks。服务独立维护，但不为服务新建 Git 分支。
10. **补齐本地管理。** 自动建立缺失的 logs 与 local-secrets 安全骨架、空总账及忽略项。Git clone 不携带这两个被忽略的目录时直接按规则 03/05 补建，不要求用户自行建文件。环境继续遵守规则 11。
11. **配置三分支与版本。** 普通开发在 main；测试专用代码/接口/数据放 test_main；人工确认精确 main 候选后才发布 release。默认只允许这三个分支，其他必须人工授权。保留目标现有 VERSION，或新建 0.1.0；配置页面底部自动显示实际版本。
12. **检查并交付。** 同步人类 HTML 文档，核对规则来源、版本、任务、忽略项和测试范围，按规则 02/04 提交推送 main。分别报告实现、测试、推送与 release 状态；未发布不写已发布。

## 分发内容

- 公共入口：AGENTS.md、CLAUDE.md、rules/README.md。
- 公共细则与来源清单：rules 内受控文件，清单见 rules/source.json。
- 项目模板：FINAL_GOAL.md、TODO.md、AI_TASKS.md、VERSION、CHANGELOG.md；目标已有项目事实需保留和重建，不照搬源历史。
- 人类文档：docs/index.html、api-interfaces.html、references.html。
- 服务说明骨架：services/README.md；不覆盖真实业务服务。
- 本地安全骨架：logs、local-secrets；只复制空骨架，或由 AI 按规则补建。
- 版本同步工具：scripts/sync-docs-version.mjs，仅供本模板静态 HTML；目标已有构建系统时适配其版本注入方式，不强制使用该工具。
- .gitignore：保留目标专用项，并补齐凭据、日志、环境、测试工作区和更新缓存忽略。

不分发 .git、真实密钥/日志、运行环境、依赖缓存、.worktrees、.cache、.rules-sync.json、旧 rules.zip 和其他生成产物。
不从旧归档恢复已退役规则；以当前受控目录和来源清单为准。

## 当前工作约定

- `main`：正常开发与自动提交推送；干净指不混入测试专用内容，不是禁止业务修改。
- `test_main`：固定 main SHA 后的隔离测试，使用独立端口/数据库/目录，不整体合回 main。
- `release`：人工确认候选后同步，并用 `v0.1.0` 等不可变标签追踪。
- 不自动创建 feature、fix、service 或协调分支；旧分支也不擅自删除。
- AI 自主判断接口与实现问题，保留确有必要的业务澄清、发布确认与危险操作批准。
- 客户资料不按凭据保密目录管理，密钥等控制信息继续按规则 05 严格本地保存。
- docs 给人看，服务 Markdown 给 AI 执行；目标、进度和活动任务按需读取。

## 偶尔自动更新

业务项目的 AI 在有修改任务执行时，默认每 7 天检查一次固定来源 main，核验快照后更新受控公共规则。
保护项目事实、专用补充、版本、业务内容和未提交改动；无网络或冲突时保留现有版本并说明，不停止无关工作。
不会创建后台定时任务，不改变业务项目 origin，不自动发布 release。详细流程见规则 18。

## 版本与预览

本项目版本来自根 VERSION；运行 `node scripts/sync-docs-version.mjs` 自动同步 docs 页脚，`--check` 只检查。
可直接打开 [项目说明](docs/index.html)，无需开发服务器。业务项目应把版本注入接入自己的构建流程。
首次上传只发布仓库 main，不代表已创建 release 或已获正式版本发布确认。
