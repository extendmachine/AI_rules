# 16. 整目录模板与初始化

## 目标

整个规范目录是可复制项目底座，不另建 templates。源码可来自用户指定本地副本或规则 18 的固定 GitHub 仓库。
只有用户要求引入/复制/初始化时才执行本流程，普通规则更新不运行整包初始化。

## 顺序

1. 确认实际源、固定版本/提交和目标项目根路径，不能把规范源误当成业务目标。
2. 盘点目标现有目标、进度、活动任务、技术栈、Git、版本及服务；保存重建需要的事实和合法项目补充，不保存秘密值。
3. 保护业务代码、数据、真实 local-secrets、日志、环境及未提交修改，协调受影响的任务。
4. 复制全部受控规范，公共文件更新到同一来源版本；按规则 06 保护并恢复项目专用补充，不用目录镜像删除未知文件。
5. 从目标副本查看新规则关键变化，重建目标、进度和任务记录，不沿用源模板历史。
6. 依据实际服务补齐 SERVICE、CONTRACT、DEPLOY、REFERENCES 和必要交接，不新建虚假服务。额外业务重构超出引入范围时只列计划。
7. 本地自动补建 logs 和 local-secrets 的安全骨架及空总账；已有真实内容保留。Git clone 不含这些被忽略的文件是正常情况。
8. 运行环境按规则 11；日志按服务/天分开，保留 30 天；不得擅自迁移其他项目或共享环境。
9. 新项目初始化 VERSION=0.1.0 与 CHANGELOG；已有项目保留其版本。按规则 17 配置实际构建的可视化页脚版本。
10. 在 main 维护正常实现，test_main 写隔离测试，人工确认后发布 release；不为新服务或并行 AI 创建额外分支。
11. 同步 docs 的真实说明、接口和官方来源，配置规则 18 的来源与本地更新记录；安装的 SHA 用实际值。
12. 完成结构、规则、版本、凭据忽略、任务状态和文档检查后提交推送 main，报告范围与未完成项；不把规范导入当成 release 批准。

## 验收

- 目标有 AGENTS、CLAUDE、规则索引、目标/进度/任务、版本与必要文档。
- 公共规则来自同一快照，项目专用要求保留，不留过期公共规则继续生效。
- 目标状态和版本是自己的，来源模板历史已移除。
- 凭据、日志、环境和缓存不进入 Git；空骨架已补齐。
- 服务职责与实际实现一致；前端页脚显示实际产品版本。
- 仅三种默认分支，test_main 的测试内容不进入 main/release。
- 更新源是用户指定仓库，更新失败不会伪报成功或阻塞无关任务。
