# 06. 目标、进度、人类文档与分发边界

## 项目记录

1. 每个项目保留 FINAL_GOAL.md、TODO.md、AI_TASKS.md；开始任务只查看当前目标、当前进度、活动任务等关键部分，不要求每次修改前全文重读。
2. FINAL_GOAL 描述最终目标、范围、不做什么和验收；用户明确修改目标时同步，不能由 AI 改写目标自行扩大权限。
3. TODO 描述当前进度、下一步、验证状态与最近记录；AI_TASKS 保存任务归属、范围和交接，两者不互相替代。
4. 权威记录位于登记的 main 工作区，由规则 14 的单写者维护；test_main 的状态文件只是候选快照。
5. 归档历史只在追溯时读取，不能把旧工作流、旧批准或旧项目状态当作当前指令。
6. 简短回执说明依据、修改、版本、验证与待办即可；只读任务不为流程要求写文件。

## 人类文档

1. 项目解释文件统一放根 docs，使用 HTML；服务 Markdown 保存 AI 需要的职责、契约、启动、日志和依赖。
2. docs/index.html 为说明入口，docs/api-interfaces.html 给人审阅接口，docs/references.html 给人审阅官方来源。
3. docs 不是独立公共规则源，但 AI 修改或核对文档时可以读取，不应误解为禁止访问。
4. 代码行为、接口或部署变化时同步相关说明，不要求无关文件每次跟着改。
5. 可视化页面底部版本按规则 17 自动同步；已有目标项目的产品版本不得被规范版本覆盖。

## 初始化与自动更新分开

- 用户要求整包复制：按根 README 和规则 16 完成初次分发、目标项目重审与初始化。
- 日常偶尔更新：仅按规则 18 更新公共规范，不重置目标、进度、版本、业务文档和真实本地数据。
- 只要求阅读或审阅：不构成复制、更新或重构授权。

## 覆盖与保留

1. 整个规范目录仍是项目底座，不创建独立 templates。公共文件按源版本覆盖，不把旧公共规则合并成另一套控制中心。
2. 覆盖前保存目标项目事实、项目专用要求、有效认领和授权；覆盖后恢复这些事实，不沿用源模板历史。
3. 公共规则与项目专用补充必须区分。自动更新只管理已核验清单中的公共文件，不能因源不存在而删除未知本地规则。整包分发遇到项目专用规则时先保留其内容，再按目标项目确认的补充位置恢复，不能无声丢失。
4. AGENTS 公共引导更新后恢复合法项目专用短提示；公共规则不得复制回入口。服务专用细则可随 SERVICE.md、CONTRACT.md 等保留，不把旧公共控制规则包装成项目补充复活。
5. 源 docs 同名模板用于新项目；已有项目必须恢复真实接口与说明事实，不用空示例长期替代。不同名业务文件不能因整包复制被删除。
6. services、logs、local-secrets 的空骨架只补缺失项，不覆盖实际服务、真实日志、凭据或已填写总账。真实 local-secrets 和日志继续禁止进入 Git。
7. Git clone 不包含被忽略的 logs/local-secrets 安全骨架；AI 按规则 03、05 在目标本地自动补建，绝不通过提交真实目录来解决分发。
8. .git、真实凭据与日志、环境、依赖缓存、工作区、规则更新缓存、旧 rules.zip 等生成归档不属于受控分发内容。
9. 对已有 .gitignore 保留有效项目专用忽略项，补齐公共安全项；不能因模板覆盖使真实凭据失去忽略。
10. VERSION、CHANGELOG 属于目标项目事实：新项目初始化，已有项目保留；rules/source.json 才追踪所安装的公共规范版本。

## 结果记录

修改任务记录真实实现、测试、main 提交推送与 release 状态；人工确认 release 的要求不因文档任务而豁免。
需要恢复项目事实时只记录不含秘密的内容或凭据路径，不复制秘密到备份说明、Git 或聊天。
